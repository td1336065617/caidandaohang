# 菜单导航 · menu_navigation

> 自动聚合同一个机器人里各插件提供的菜单，把整机可用指令整理成一张图 —— 用户只要发一条 `菜单`，就能看到全部插件能做什么。

```text
各插件目录
├── menu.md                     ┐
└── metadata.yaml  ─ menu: …    ┘
        │  读取菜单原文（menu.md 优先，其次 metadata 的 menu 字段）
        ▼
提取指令摘要（_extract_menu_items）
   分组行 → 作用范围（所有人 / 仅管理员）
   条目行 → 指令 + 说明（按分隔符切分）
        │
        ▼
计算签名（缓存格式版本 + 勾选插件 + 各插件 metadata 与菜单原文）
        │
        ├── 签名未变 ──► 复用已有图片
        └── 签名变化 ──► 渲染
                 HTML ──► Chromium / Firefox / wkhtmltoimage
                 （无可用浏览器时）Pillow 直接绘制 PNG
                        │
                        ▼
                 发送 1 张 PNG；全部渲染方式不可用 ──► 纯文本分片续发
```

- **版本**：1.2.6 ｜ **支持平台**：`qq_official`（QQ 官方机器人适配器）｜ **许可**：见文末「许可」
- **适配 AstrBot**：`>=4.13.0,<5`（`metadata.yaml` 的 `astrbot_version`）
- **依赖**：`pyyaml`（必需，解析 `metadata.yaml`）+ `Pillow`（可选，仅在没有任何浏览器时用于兜底绘制）

## 功能

### 🧭 聚合菜单

- 触发指令为 `菜单` 与 `菜单导航`，**全匹配**：去掉一个前缀 `/` 之后必须正好等于这两个词之一，因此不会误伤正常聊天内容。
- 兼容 QQ 官方指令面板自动补上的斜杠：`/菜单`、`/菜单导航` 与无前缀写法等效。
- 群聊无需 @机器人，私聊同样可用；仅处理 `qq_official` 适配器的群消息与私聊消息。
- 只扫描 AstrBot 插件目录下的**直接子目录**（跳过隐藏目录），按目录名排序展示。
- 菜单导航**自己也作为一个分区**出现在聚合菜单里（列出 `菜单` 与 `插件介绍`），
  且不受 WebUI 勾选影响——否则「插件介绍」这个入口在只勾选部分插件时会消失。
- **每个插件都会自动补一条属于它的介绍指令**（如 `插件介绍 acmerQQ群机器人`）：
  位置是**紧跟该插件自己的「XX菜单」条目之后、且留在第一个分组（所有人可用）内**——
  不会落到「仅管理员」等其它分组里，也不会无脑追加到分区末尾。
- 每个插件取 `metadata.yaml` 的 `display_name`（其次 `name`，再其次目录名）作为标题；菜单内容只提取「指令 + 说明」条目，附上分组与开源仓库链接，不会把整篇说明原样拼进去。
- 插件没有可识别的菜单指令时，展示其 `short_desc`（其次 `desc`，超过 120 字符截断）作为简述。

### 📖 插件介绍

- 触发指令为 `插件介绍`（别名 `功能介绍`、`插件说明`、`插件详情`），同样**全匹配**；
  它同时列在聚合菜单的「菜单导航」分区里，用户发 `菜单` 就能看到这个入口。
- 分工：**菜单只放"用户发送后会触发功能"的指令**，机器人主动推送（定时早报、赛前提醒、
  赛后推送、后台巡检等）不进菜单，统一放在插件介绍里。
- 与「聚合菜单」的区别：菜单只列指令，插件介绍**把每个插件的具体功能讲清楚**，
  包括菜单表达不了的**主动触发能力**（定时早报、赛前提醒、赛后推送、后台巡检等）。
- 支持只看一个插件，两种写法都行：`插件介绍 acmer`（前缀 + 关键字）与
  `acmer插件介绍` / `群管理插件介绍`（插件名 + 后缀）；关键字按目录名或显示名匹配，忽略大小写。
  菜单里每个插件分区末尾会自动列出这种写法，用户直接照抄即可。
- 内容来源：插件根目录的 `intro.md`（其次 `metadata.yaml` 的 `intro` 字段）；
  都没有时回退到该插件的 `desc`/`short_desc`，保证每个插件都有内容可看。
- 与菜单一样优先渲染成图片、失败回退纯文本；图片与缓存状态各自独立
  （`intro.png` / `intro_cache.json`），不会与菜单互相顶掉。

### 🎨 图片渲染

- 固定宽度 1200 像素；高度按内容估算（`120 + 行数 × 46`），下限 760、上限 12000 像素。
- 渲染器按顺序自动探测：环境变量指定 → `chromium` → `chromium-browser` → `google-chrome` → `google-chrome-stable` → `firefox` → `wkhtmltoimage`，每个外部渲染器最多等 30 秒；都失败时用 Pillow 绘制同一份内容；Pillow 也不可用（未安装或找不到中文字体）才退回纯文本。
- 每一份渲染结果都会做 PNG 校验（文件存在、非空、PNG 魔数正确），损坏或空白图不会被当成成功结果，会继续尝试下一个渲染器。
- **中文字体**：优先用环境变量指定的字体文件，否则通过 `fc-match` 查找 `Noto Sans CJK SC`，再退到常见系统路径（Noto Sans CJK、文泉驿正黑、Droid Sans Fallback）。TTC 字体会显式选择简体中文面（`NotoSansCJK` 默认使用 index 2），避免误加载日文字面导致中文方框或字形错乱；HTML 侧使用同一组字体族。
- **Emoji 字体**：插件自带 `assets/fonts/NotoColorEmoji.ttf`，不要求服务器安装 Emoji 字体。HTML 通过 `@font-face` 以内置字体的本地文件地址加载；Pillow 回退会先用高分辨率（首选 109px）绘制 Emoji 再缩放贴回，并与中文按实际绘制宽度一起测量、换行；Emoji 字体加载失败时按内置对照表使用安全符号兜底（`👥`/`🔑`/`🌙`/`📢` → `◆`，`🌸` → `✦`，`🎴` → `▣`，`🔗` → `↗`，`⚙️` → `⚙`），而不是画出方框。
- 版式为樱粉 / 珍珠白配色的卡片式菜单（HTML 内联样式与 Pillow 绘制保持一致），成功时只发送这一张 PNG。

### 📝 纯文本分片

- 渲染不可用、处于失败冷却期或菜单为空态时，改用纯文本发送。
- 单条消息最长 1500 字符；分片优先在换行或空格边界断开，尽量不切断词句。
- 第 2 条起的续片带 `……（接上条）` 标记，方便在聊天流里辨认顺序。

### 💾 缓存与失效

- 缓存目录为 `AstrBot/data/plugin_data/menu_navigation/`，其中 `menu.png` 是菜单图片，`cache.json` 记录缓存格式版本、签名与图片文件名。
- 签名是 `缓存格式版本 + 参与聚合的插件目录集合 + 各插件目录名/metadata 原文/菜单原文` 的 SHA-256，只要任一插件的菜单或元信息变化，签名就会变。
- 只有收到 `菜单` 触发时才扫描插件并计算签名：签名未变且图片仍在则直接复用（内存缓存），否则尝试磁盘缓存（格式版本与签名都匹配、且 PNG 有效才复用），再否则重新渲染并写入 `cache.json`。
- 渲染失败后会记住该签名并进入 300 秒冷却：冷却期内同样的菜单直接发纯文本，不再重复尝试几十秒的超时渲染。
- 在后台修改参与聚合的插件范围会立即清空内存缓存；缓存格式版本升级（当前为 8）会让旧图片自动失效并重绘。

### 🖥️ WebUI 选择参与聚合的插件

- 配置页位于 AstrBot 管理面板 → 插件管理 → **菜单导航**，对应源码 `pages/settings/index.html`。
- 默认「整合全部插件」：现有插件与以后新装的插件都会自动纳入。
- 关闭后进入自选模式，在插件列表中勾选需要整合的插件，保存后立即生效，并使旧菜单图片缓存失效。
- 插件列表会标注每个插件是「已识别菜单指令」还是「无可识别菜单，将显示简述」；菜单导航插件自身不会出现在可选项里。
- 保存时只接受仍然真实存在的插件目录名（未知目录名会被丢弃，重复项会去重）。

### 🫙 空态处理

- 找不到插件目录、没有扫描到插件、或已启用的插件都没有可识别菜单时，会分别给出不同文案（「未找到插件目录」/「暂未发现提供菜单的插件」/「已启用插件均未提供可识别菜单」）。
- 空态不渲染图片，直接发送纯文本，避免生成无意义的空白图。

## 安装与使用

### 安装

1. AstrBot 版本需满足 `>=4.13.0,<5`，并已启用 **QQ 官方机器人** 适配器（`qq_official`）。
2. 在 AstrBot 插件页填入仓库地址安装：

```text
https://github.com/td1336065617/caidandaohang/tree/master
```

也可以手动把本目录放到 `AstrBot/data/plugins/menu_navigation/`，然后重启或重载 AstrBot。

3. 安装依赖：`pyyaml` 与 `Pillow` 见仓库 `requirements.txt`（其中 PyYAML 是必需项，Pillow 只在没有浏览器时用于兜底绘制）。

### 使用

1. 在群里或私聊发送 `菜单`（或 `菜单导航`），无需 @机器人。
2. 首次触发会扫描全部插件、渲染图片并写缓存；之后只要各插件的菜单没变化，就直接复用已有图片。
3. 想看某个插件的指令，直接在聚合菜单里找到对应插件卡片即可。

### 配置聚合范围

打开 AstrBot 管理面板 → 插件管理 → **菜单导航**（配置页），默认整合全部插件；如需精简，关闭「整合全部插件」，在列表中勾选需要的插件并保存。更多配置说明见 [docs/CONFIG.md](docs/CONFIG.md)。

## 插件接入约定

任何插件都可以零代码接入菜单导航，只要在**插件根目录**提供 `menu.md`，或在自己的 `metadata.yaml` 里声明 `menu` 字段即可。

### 方式一：`menu.md`（优先）

在插件根目录放置 `menu.md`，内容为要展示的菜单文本。它优先于 `metadata.yaml` 的 `menu` 字段；文件为空或读不到时才会回退到 `menu` 字段。

### 插件介绍：`intro.md`（可选）

想让插件出现在 `插件介绍` 里，在插件根目录放 `intro.md`（或在 `metadata.yaml` 里声明 `intro` 字段）。
与 `menu.md` 不同，**这里保留完整富文本**，用来讲"这个插件到底能做什么"：

```markdown
## 比赛查询
- 最近比赛 ─ 汇总四平台未来 N 天内及进行中的比赛
- nk比赛 ─ 牛客全部未开始比赛

## 主动推送（无需指令）
- 每日早报 ─ 每天 08:00 推送当天比赛
- 赛前提醒 ─ 比赛开始前 15 分钟提醒
```

解析规则：`##` 开头的行为分组标题（渲染成 `◆ 标题`）；`-`/`*`/`•` 开头的行按
`指令 ─ 说明` 切分（冒号同样可以当分隔符）；其余非空行整行保留为说明文字
（不会再被冒号切碎）；单个插件最多渲染 60 行。不提供 `intro.md` 时回退到
`metadata.yaml` 的 `desc`，所以不写也有内容。

### 方式二：`metadata.yaml` 的 `menu` 字段

```yaml
menu: |
  表情包管理菜单
  👥 所有人可用
  • 添加{关键词} ─ 回复图片批量入库
  • 来只{关键词} - 随机发送一张图片
```

`menu` 可以是多行字符串，也可以是列表：

- 列表元素是字符串时，按行使用；
- 列表元素是映射时，取 `command`（其次 `name`）作为指令、`description`（其次 `desc`）作为说明，拼成 `指令 ─ 说明`；没有说明时只有指令。

```yaml
menu:
  - command: 添加{关键词}
    description: 回复图片批量入库
  - 来只{关键词} - 随机发送一张图片
```

### 解析规则

菜单导航会逐行读取菜单原文（行内连续空白先折叠为单个空格），按下面的规则处理：

**会被忽略的行**

- 空行；
- 纯分隔线：整行只由 3 个及以上空格、`-`、`_`、`=`、`─`、`—`、`–`、`━` 组成（例如 `-----`、`===`）；
- 以 `#`、`提示`、`说明`、`⚙️`、`🔗` 开头的行（用于写标题、注意事项、补充说明）。

**分组行（作用范围）**

- 判定规则：行内含「管理员」即视为分组行；或者同时含「所有人」以及「用」或「可」也视为分组行。
- 标签固定渲染为 `🌙 仅管理员`（含「管理员」时）或 `👥 所有人可用`（其余情况），你写什么 emoji 不影响结果。
- 分组行本身不产生条目，它把**之后**的条目都归入该分组，直到出现下一个分组行；没有分组行的条目分组为空。
- 注意：判定在条目解析之前，所以条目行里只要出现「管理员」三个字，整行会被当成分组行丢弃（例如 `• 管理员指令 - 说明` 不会出现在菜单里）。

**条目行**

- 项目符号：`-`、`*`、`+`、`•`、`●`、`▪`、`◦` 后跟一个空格；有项目符号的行即使没有分隔符也会收录，整行作为指令。
- 没有项目符号、又没有分隔符的行会被忽略（当作普通标题或说明），所以标题行不会变成指令条目。
- 分隔符取**第一个**匹配位置切开，前半是指令、后半是说明，两种写法：
  - 破折号：`─` / `—` / `–` / `-` 的 1–3 个，**前后必须有空白**，例如 `指令 - 说明`、`指令 ─ 说明`、`指令 —— 说明`；写成 `指令-说明`（无空格）不会被切开。
  - 冒号：全角 `：` 或半角 `:`，前后空白可有可无，例如 `查询状态：查看当前状态`。
- 指令会去掉首尾的反引号与空格；指令长度超过 120 字符的条目会被丢弃。
- 说明超过 180 字符会截断并补 `…`；没有说明的条目只有指令。

### 最小示例

```markdown
🌸 我的插件

👥 所有人可用
• 查询状态 ─ 查看当前状态
• 我的数据：查看个人数据

🔑 仅管理员
- 开启功能 - 打开功能开关
```

上面的 `🌸 我的插件` 没有项目符号也没有分隔符，会被忽略（正好可以当标题）；两个分组行分别把后续条目归入「所有人可用」与「仅管理员」，最终渲染成 3 条指令。

### 其他会被读取的字段

- 标题：`display_name` → `name` → 插件目录名（折叠多余空白）。
- 简述（无可识别菜单时展示）：`short_desc` → `desc`（折叠空白，超过 120 字符截断）。
- 开源链接：`repo` 字段会以 `🔗 开源：<地址>` 的形式附在该插件卡片下方。
- 三者都没有、又没有可识别菜单的插件会被整体略过；但只要有 `metadata.yaml` 或菜单文件，插件就会被计入菜单指纹，之后补充 `menu.md` 时下一次触发即可自动更新。

## 配置

配置入口：AstrBot 管理面板 → 插件管理 → **菜单导航**。

| 配置项 | 默认 | 说明 |
| --- | --- | --- |
| `include_all` | 开 | 「整合全部插件」。开启时聚合所有插件（含以后新装的）；关闭后只聚合勾选的插件 |
| `enabled_plugins` | 空 | 自选模式下参与聚合的插件目录名列表；保存时只保留真实存在的目录名并去重 |

后台配置保存在 AstrBot 的插件 KV 存储中，保存后立即生效并清空图片缓存。

没有可视化配置项、只能用环境变量调整的行为：

| 环境变量 | 说明 |
| --- | --- |
| `MENU_NAVIGATION_RENDERER` | 指定优先使用的渲染器：可执行文件名、绝对路径，或 `pillow`（`pil` 亦可）。它会被排到候选列表最前面，其后的内置候选仍会依次尝试 |
| `MENU_NAVIGATION_BROWSER` / `MENU_NAVIGATION_CHROME` | 与 `MENU_NAVIGATION_RENDERER` 等价的旧写法，仅在后者未设置时生效 |
| `MENU_NAVIGATION_FONT` | 指定中文字体文件；TTC 字体会自动选择简体中文面 |
| `MENU_NAVIGATION_FONT_INDEX` | 指定字体面索引（默认对 `NotoSansCJK` 的 TTC 使用 index 2） |
| `MENU_NAVIGATION_EMOJI_FONT` | 覆盖内置 Emoji 字体 |
| `MENU_NAVIGATION_EMOJI_FONT_INDEX` | 指定 Emoji 字体的字体面索引 |

以下为代码中的固定常量，不是用户配置项，仅供排查问题时对照：单条纯文本上限 1500 字符、图片宽度 1200 像素、图片高度 760–12000 像素、渲染失败冷却 300 秒、缓存格式版本 8。

## 常见问题

**菜单图片发不出来，只收到一大段文字？**
说明所有渲染方式都没成功，走的是纯文本兜底。插件日志里会有 `菜单导航没有可用的 HTML/图片渲染器，改用纯文本发送`。解决办法二选一：装上并保证可用的浏览器（Chromium/Chrome、Firefox、`wkhtmltoimage` 任一），或安装 `Pillow` 并保证服务器上存在简体中文字体；也可以直接用 `MENU_NAVIGATION_RENDERER` 指定渲染器路径，或指定为 `pillow` 优先用 Pillow 绘制。

**图片里中文显示成方框或字形错乱？**
通常是字体选择到了不含简体中文的字面（例如 NotoSansCJK 的日文字面）。设置 `MENU_NAVIGATION_FONT` 指向简体中文字体文件；如果是 TTC，用 `MENU_NAVIGATION_FONT_INDEX` 指定正确的字体面（`NotoSansCJK` 的简体面是 index 2）。

**Emoji 变成了方框里的 X 或奇怪符号？**
插件已内置 `assets/fonts/NotoColorEmoji.ttf`，正常情况不需要服务器安装 Emoji 字体。若仍显示异常，可用 `MENU_NAVIGATION_EMOJI_FONT` 指定其他 Emoji 字体；字体完全加载失败时，插件会用安全符号（`◆`、`✦`、`▣`、`↗`、`⚙`）替代 Emoji，因此不会出现方框。修改字体后需要菜单内容或缓存格式版本发生变化才会重绘。

**我的插件没出现在菜单里？**
依次检查：① 插件目录下有 `menu.md`，或在 `metadata.yaml` 里声明了 `menu`；② 菜单里至少有一行能被解析成条目 —— 没有项目符号又没有分隔符的行会被忽略，含「管理员」字样的条目行会被当成分组行丢弃；③ 后台是否关闭了「整合全部插件」但没勾选这个插件；④ 插件目录名是否以 `.` 开头（会被跳过）；⑤ 菜单导航自身不会出现在菜单里。

**菜单太长，图片好像被截断了？**
图片宽度固定 1200 像素，高度按内容估算（`120 + 行数 × 46`），上限 12000 像素（约 250 行）；超过上限的内容不会再撑高画布，可能被裁掉。建议在后台关闭「整合全部插件」，只勾选需要的插件，或精简各插件 `menu.md` 里的条目数量。纯文本兜底不受此限制，但会按 1500 字符分片、连发多条并带 `……（接上条）` 标记。

**触发一次「菜单」要卡几十秒？**
常见于服务器上存在浏览器但渲染不可用的情况：每个外部渲染器最多等 30 秒，多个候选会依次尝试。插件在渲染失败后会对同一份菜单进入 300 秒冷却，冷却期内直接发纯文本，不会每次都重试。建议装好一个真正可用的渲染器（或用 `MENU_NAVIGATION_RENDERER` 指定），或指定为 `pillow` 跳过浏览器尝试。

**改了别的插件的 `menu.md`，菜单会更新吗？**
会。菜单原文属于菜单指纹的一部分，下一次发送 `菜单` 时会检测到变化并重新渲染，不需要重启 AstrBot；没有变化时直接复用已有图片。

**群里任何人都能触发「菜单」吗？**
匹配逻辑只看消息文本（全匹配 `菜单` 或 `菜单导航`），插件内部不做权限判断，因此任何能触发机器人的成员都可以查到这份聚合菜单。

## 开发

### 目录结构

```text
menu_navigation/
├── main.py                     # 插件全部逻辑：扫描、解析、渲染、缓存、指令
├── metadata.yaml               # AstrBot 插件元信息（版本、仓库、支持平台等）
├── requirements.txt            # pyyaml（必需）、Pillow（兜底绘制）
├── pages/settings/index.html   # 后台配置页（选择参与聚合的插件）
├── assets/fonts/               # 内置 NotoColorEmoji.ttf 及其许可文件
├── docs/CONFIG.md              # 配置说明
├── CHANGELOG.md                # 更新日志
└── README.md
```

### 渲染回退链

1. `_render_image()` 先写出菜单 HTML（`menu.html`）。
2. `_find_renderers()` 返回候选渲染器列表（环境变量指定的排在最前，其后是内置候选），逐个执行 `_run_external_renderer()`，每个超时 30 秒。
3. 任一外部渲染器产出的图片通过 `_is_valid_png()`（存在、非空、PNG 魔数正确）即被采用。
4. 外部渲染器全部失败后再单独尝试一次 `_render_with_pillow()`。
5. 仍然失败就返回 `None`，由 `_ensure_menu_image()` 记录失败签名并进入 300 秒冷却，改用纯文本分片发送。

### 如何新增一种渲染方式

1. 在 `_find_renderers()` 的候选列表中加入可执行文件名（或让使用者通过 `MENU_NAVIGATION_RENDERER` 传入）；
2. 在 `_run_external_renderer()` 中按 `kind` 增加对应的命令行分支 —— `kind` 由可执行文件的 basename 判定：含 `firefox` 的按 Firefox 处理，含 `wkhtmltoimage` 的按 wkhtmltoimage 处理，其余按 Chromium 系的无头参数处理（Chromium、Chrome、Edge、Brave 等通用）。

返回值会被 `_render_image()` 依次尝试，因此新方式只要写出有效 PNG 就会被采用，无需改动其它逻辑。

### 修改解析规则或版式时

- 解析相关：`_extract_menu_items()`（条目提取）、`_is_scope()` / `_scope_label()`（分组判定）、`_SEPARATOR_RE` / `_BULLET_RE` / `_DIVIDER_RE`（分隔符、项目符号、分隔线正则）、`_read_menu()`（菜单来源优先级）。
- 版式相关：HTML 见 `_html_for_snapshot()`，Pillow 见 `_render_with_pillow()`，两者需要保持一致；Emoji 与中文的混排测量也在这里。
- 改动输出内容或版式后，请提升 `CACHE_FORMAT_VERSION`，否则旧图片可能被继续复用。

### 关于测试

仓库当前不包含自动化测试套件（只有 `main.py`、后台页面与文档）。改动后建议按下面的方式自检：

1. 在群里或私聊发送 `菜单`，确认收到图片；日志会打印 `菜单导航已使用 <渲染方式> 将 HTML 转为图片`（外部渲染器全部失败、最后靠 Pillow 兜底时是 `菜单导航已使用 Pillow 兜底生成图片`）。
2. 检查 `AstrBot/data/plugin_data/menu_navigation/` 下的 `menu.png` 与 `cache.json`，确认图片有效、签名被写入。
3. 临时移除中文字体或渲染器，确认回退链能一路退到纯文本，并且失败后进入冷却（不会每次都卡住）。
4. 解析规则可以脱离 AstrBot 单独验证：把 `_extract_menu_items()`、`_is_scope()`、`_scope_label()` 与三个正则复制到一段临时脚本里，喂入样例 `menu.md` 检查提取结果是否符合预期。
5. 插件介绍自检：发送 `插件介绍`（或 `插件介绍 <关键字>`）确认图片与纯文本兜底；
   检查 `AstrBot/data/plugin_data/menu_navigation/intro.png` 与 `intro_cache.json` 是否生成，
   并确认 `menu.png` / `cache.json` 没有被覆盖。
